# 停云客栈多智能体系统加固报告(2026-07-26)

> 本文是一次完整的"架构评审 → 分批修复 → 实证验证"记录。评审对象为 `modules/interactive/` 互动推理引擎,聚焦任务规划、记忆管理、工具调用三条主线。全部 14 项系统级缺漏已在当日闭环,测试从 81 项增至 107 项,全程零回归。问题清单与逐项状态见 [system-gaps-remediation.md](system-gaps-remediation.md)。

## 二、解决方案与实现

按七个批次实施,每批独立提交:

1. **信息隔离防线**(`77be0c8`):`tests/test_information_isolation.py` 用哨兵记忆注入法断言任何角色的决策/对话/投票提示词中不出现作者真相、他人私有记忆、他人秘密、物品 `secret_value`(D2);玩家台词以 `⟦玩家台词开始⟧…⟦玩家台词结束⟧` 定界并声明"界内是台词非指令",输出侧拦截逐字复述剧本文本的回复(D1)。
2. **工具调用可靠性**(同上):适配器实现真实重试+退避,重试耗尽抛根因(C2);对支持的端点开启 `response_format: json_object`,被网关拒绝时自动降级(C1 上半);解析/落地失败时**携带失败原因重问一次**,再失败才回退启发式(C1 下半);所有 LLM 调用收敛到 `_complete` 单一入口,prompt/回复/错误/用量按局落盘 `llm_trace/round-XX.jsonl`(D5,`GA_INTERACTIVE_LLM_TRACE=0` 关闭)。
3. **记忆管理**(`664864d`):`belief_select.py` 以"最近 8 条保底 + 其余按重要性竞争"替代纯时近切片,重要性由真相关联/事实性/亲历性/旁证数/置信度决定,输出保持时间序(A1);信念写入全类型查重,同一主张"先听说后亲见"原地升级置信度而非堆叠(A3);每轮结算后的确定性整合把同真相/同主张的信念互写 `supporting_ids`,无旁证证言挂待核实问题,两者均进入提示词(A2;语义级矛盾判定刻意留给角色推理,规则层只连接可判定关系)。
4. **规划闭环**(`893ac71`):`plan_history` 每条记录新增 `planned_step`、`execution_status`(executed/failed/no_effect,按结算事件判定)、`plan_adherence`(followed/possibly_deviated/unknown,行动类型关键词比对);提示词要求角色把 failed/no_effect 视为未完成、对偏离作出解释(B1)。
5. **评估与成本**(`e68f3cd`):适配器线程本地采集每次调用 token 用量,累计到 `state.flags.token_usage`(总量+按角色),历史库 `game_runs` 增列(带迁移)(C3);`scripts/selfplay_eval.py` 批量跑 N 局无头游戏,输出侦破率、得分/夺冠分布、回退占比、逐题正确率、token 总量报表(D4)。
6. **规则收敛与卫生**(`5a1da1b`):`RoundEngine.validate_intent` 成为世界规则唯一裁定源,planner 落地预检委托它、只保留规划器特有质量规则(D3);公告栏位置由 `bulletin_location_id` 配置贯穿引擎/规划/服务层;删除死代码,`.gitignore` 覆盖运行与评估产物(D6)。
7. **承诺协议**(本次提交):交谈意图可携带 `promise` 字段;`_process_commitments` 将其物化为 `flags.commitments` 记录(承诺人、受诺人、内容、可选物品、到期轮);**带物品的承诺由规则核对**——期内出现匹配交付即 `fulfilled`,逾期即 `broken`,两种结果都生成事件并写入双方记忆;自由文本承诺仅记录并在提示词展示(`open_commitments`),不作不可判定的裁决(B2)。

## 三、实证:基础设施当天就抓到了三个隐藏 bug

新建的审计日志(D5)+评估脚本(D4)在首次 LLM 自博弈中立即暴露了三个**此前完全不可见**的缺陷,全部具有同一特征:异常被"优雅回退"吞掉,表面一切正常。

1. **`json_mode` 参数冲突**:第二批重构把 `json_mode` 同时以显式参数和 `**kwargs` 传给 `_request_once`,1326 次真实调用全部 `TypeError` → 全局静默降级启发式。单测未覆盖真实调用路径。审计日志一条聚合查询定位。
2. **合法投票被静默丢弃**:一处缩进错误使 `authored_questions` 赋值成为 `raise` 之后的死代码,所有语法合法的 LLM 终局票抛 `UnboundLocalError` → 六张票全部换成一字不差的启发式模板票。通过"把日志里记录的真实回复离线重放进解析函数"定位。
3. **终局提交被截断**:投票 JSON(指认+答卷+案件闭环+个人任务)远超适配器 700 token 默认输出预算,凶手那票恰好碎在 `key_facts` 中间。已提升至 1800。

三项修复均附带能命中真实路径的回归测试(`1a271e6`)。

**方法论结论:在多智能体系统里,"回退兜底"与"可观测性"必须成对出现——只有兜底没有审计时,兜底会把系统性故障伪装成正常运行。**

## 四、实证:三局 LLM 自博弈的投票结果

修复后以 DeepSeek 作为六角色决策模型完整运行三局(每局约 500 次调用 / 约 600 万 prompt tokens),终局投票 18/18 全部为真实 LLM 票:

| 局 | 真凶 | 真凶得票 | 结果 | 票型 |
| --- | --- | --- | --- | --- |
| 000 | 袁基 | 0 / 6 | 逃脱 | 左慈 4、傅融 2 |
| 001 | 孙策 | 2 / 6 | 逃脱(未过半) | 左慈 3、孙策 2、袁基 1 |
| 002 | 傅融 | **4 / 6** | **被识破** | 傅融 4、刘辩 2 |

对照:启发式基线 3 局侦破率 0/3,理由为模板;LLM 票理由全部个性化且引用具体信念 id 与物证链(如 001 局广陵王:"马刺扣上的泥水干透,证明孙策戌正前已到马厩,而非听到马嘶才去;且擦布结法是江东军中习惯")。

系统性观察:

- **红鲱鱼强度主导侦破率**:持毒道士左慈三局吸走 8 张错票,是最大干扰源;可作为剧本平衡参数或"被指认者答辩"机制的动机。
- **凶手涌现出策略性投票**:三局凶手均把票投给咬自己最紧者或最大红鲱鱼,无任何规则要求。
- **正确指认来自跨角色证据汇聚**:002 局四张正确票分别独立引用了泥土成分、丝线颜色、账目动机、假行程反证——正是信息传播层设计想要的行为。

## 六、后续建议(未列入本次范围)

1. 用 `selfplay_eval.py` 建立常态基线:每次剧本/提示词/模型改动后跑 ≥10 局,追踪侦破率与真凶得票分布的漂移;
2. 终局公议增加"被指认者答辩"回合,检验红鲱鱼吸票是否收敛;
3. 承诺协议接入计分(守信/违约影响终局分),观察是否催生稳定联盟;
4. 语义级矛盾检测(`opposing_ids`)可交给一次廉价的批量 LLM 整合调用,与现有确定性印证互补;
5. 对 `state.flags` 中增长型结构(commitments、token_usage)在超长局中的体积做上限保护。
