# 2026-08-06 互动体验改造与调试记录

## 本次目标

根据真实玩家反馈，集中改善自由探索阶段的节奏、移动与交谈操作、聊天阅读体验，以及角色转述情报时的人称和语用自然度。同时确认本地 Ollama 与 DeepSeek API 两条模型链路都能可靠工作。

## 最终设计与实现

### 四轮限时探索

- 游戏调整为 4 轮，每轮时限依次为 6、8、10、15 分钟。
- 每轮主要行动额度依次为 3、4、5、6 次，共 18 次。
- Agent 默认每 30 秒获得一次行动机会；可以放弃行动，但行为手册要求尽量主动执行计划。
- 玩家等待 Agent 对话回复时暂停有效计时，避免模型延迟挤占玩家探索时间。
- 玩家可以提前结束本轮；此后未完成的 Agent 行动加速结算，全员回到大堂进入轮末讨论。

### 地图、移动与聊天界面

- 地图只高亮相邻可达房间，点击房间后确认移动。
- 点击同一房间的角色直接打开对应对话页。
- 移动和发言不再弹出打断阅读的反馈框，事件直接进入聊天记录。
- 私下交谈沿用按角色分组的聊天页；大堂讨论使用共享对话页，并显示发言者头像。
- 移动与普通交谈属于自由行动，调查等主要行为才消耗本轮行动额度。

### 信息视角与转述

- 记忆增加说话者、视角主体、见证者和获知地点等结构化信息。
- 模型上下文中的记忆先渲染为当前角色的第一人称视角，避免把“我经历的事”机械转述成对玩家说“你……”。
- 情报交换保留来源和传播链，防止同一信息被重复包装成新情报。

## 关键故障与根因

### 玩家寒暄后 Agent 机械抛出情报

复现现象：玩家只说“楼主！”，Agent 却直接讲述丝线、账册等案件线索。

根因不是单一提示词问题，而是两层故障叠加：

1. DeepSeek 请求在建立连接时触发 `WinError 10013`，对话没有得到真实模型回复。
2. 最终启发式兜底会预先选择最近一条可分享记忆，并在分析玩家话语之前直接输出该记忆，因此任何寒暄都可能触发情报交换。

修复：

- 默认模型改为本地 Ollama `qwen2.5:7b-instruct`。
- 主动选择 DeepSeek 或项目 API 时，调用链改为“远端模型 → 本地 Ollama → 启发式规则”。
- 每次实际调用记录真实 provider 和来源，能够区分远端成功、本地回落与规则兜底。
- 对话提示词只保留人物上下文、知识边界、安全边界和结构化输出要求；语气、长度、话题推进及是否透露情报交给角色自行决定。
- 启发式兜底只有在玩家确实询问信息时才考虑分享记忆，短寒暄只做自然回应。

### DeepSeek API 无法连接

初始错误发生在 TCP 连接阶段，并非认证失败或模型名错误。进一步验证结果：

- `DEEPSEEK_API_KEY`/兼容变量已加载，测试过程未输出密钥。
- 在允许外网访问的本机上下文中，`https://api.deepseek.com` 使用 `deepseek-v4-flash` 的最小请求成功返回 `OK`。
- 游戏服务改用具备外网访问权限的启动上下文后，真实游戏对话成功完成。
- 对话事件和原始轨迹均记录为 `deepseek:deepseek-v4-flash`、`llm`，没有静默回落到 Ollama。

结论：API Key、TLS、模型端点和适配器均正常；此前失败来自启动游戏服务的受限网络环境。

## 后续观察点

- 本地 7B 模型的回复速度与细节稳定性仍受机器负载影响，轮末多角色讨论会明显慢于规则模式。
- “自由发挥”不等于允许编造已发生事件；现有落地校验和真相泄漏检查应继续保留，并根据真实对话记录迭代。
- 旧六轮存档目前保持兼容，不自动转成四轮。
- 后续对话质量评估应区分模型原始输出、Ollama 回落和启发式兜底，避免把基础设施故障误判为角色设定问题。
