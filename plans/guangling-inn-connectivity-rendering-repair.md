## Bug 调查结论

### 1. 前端没有消费已经声明的视觉端口

`map_binding.json` 虽然包含 `visual_join`、`ports` 和 `connection_kit`，但当前 `interactive_map.js` 的 `routeMarkup()` 只遍历 `segments`，然后统一输出 SVG `<path>`。

因此：

- `seam` 没有被识别为门洞或门框；
- `portal` 没有被识别为楼梯、石阶或室外入口；
- 标准门框资产没有被前端使用；
- 除跨层楼梯外，路线缺少明确的端点标志；
- 玩家看到的是抽象折线，而不是建筑出口。

### 2. 动画路径和连通性视觉混为同一数据

当前 `segments` 同时承担两种职责：

1. 小人移动动画的采样路径；
2. 玩家长期可见的连通线。

动画需要连续坐标，但连通性 UI 应优先显示门、石阶、楼梯和入口。把同一折线永久显示，使地图看起来像编辑器调试界面。

### 3. 现有路线数据存在零长度和端点错误

自动审计结果如下：

| 连接 | 当前长度/偏差 | 问题 |
|---|---:|---|
| 马厩 ↔ 后院 | 0px | 对 `seam` 可以成立，但前端没有改为门框渲染 |
| 马厩 ↔ 正门 | 580px | 长折线沿画布外缘绕行，像线路图而非有顶通道 |
| 后院 ↔ 后厨 | 65px | 只显示边界竖线，没有两端门口语义 |
| 后院 ↔ 大堂 | 0px | `svg` 路线不可见，也没有门口标志 |
| 大堂 ↔ 后厨 | 383px；终点偏离端口 64px | 路线绕至画布右缘，未落在后厨声明端口 |
| 后厨 ↔ 地窖 | 154px | 已有石阶美术，但仍叠加虚线路径 |
| 木梯 ↔ 大堂 | 60px | 只显示竖线，没有门或入口标志 |
| 正门 ↔ 大堂 | 0px | `svg` 路线不可见，也没有入口标志 |
| 木梯 ↔ 二层回廊 | 73px/层 | 已有楼梯美术，但仍以路径和圆点承担主要提示 |

二层四条“客房/账房 ↔ 回廊”路线也都是零长度 SVG。它们不一定出现奇怪长线，但同样缺少真实门口表现。

### 4. 路线覆盖在房间美术之上

当前层级为：

- floor art：z=0；
- 房间交互层：z=2；
- SVG 路线层：z=3；
- 角色层：z=5。

路线直接压在房间美术上，即使颜色很淡，也会被理解成地图上的电线、边框或调试辅助线。

### 5. 每个房间都存在一个与数据无关的“门”提示

当前 `roomMarkup()` 无条件给每个房间右下角添加 `room-door-hint`。这个“门”不读取端口数量、方向或连接目标：

- 一个房间可能有多个出口，却只显示一个固定位置的“门”；
- 没有出口的边缘也可能被误认为可通行；
- 移动端又会隐藏这个提示，桌面和移动端语义不一致。

### 6. 现有验证没有覆盖“能否看懂连通性”

当前检查可以证明规则图、端口和房间矩形合法，但没有验证：

- `segments` 首尾是否落在对应 `ports`；
- 非 `seam` 路线是否为零长度；
- 路线是否越界、绕过不相关房间或遮挡内容；
- 每条规则连接是否产生可见的门/入口；
- 悬停房间时是否只高亮真实相邻地点。

浏览器烟测只统计 13 个 `.map-route` DOM 节点。即使其中路径长度为 0 或坐标错误，测试仍会通过。

## 推荐设计

采用“建筑出口常显 + 当前相邻关系高亮 + 完整连通图按需显示”的三层表达，而不是永久展示整张线路网。

### 1. 建筑出口层

始终显示低亮度的真实出口：

- 普通门：标准门框或门口徽记；
- 有顶通道：两端带屋檐的通道入口；
- 地窖：石阶/暗门入口；
- 主楼梯：完整楼梯下段与二层到达平台；
- 同层但无法形成自然物理接缝的连接：在两个端点分别显示配对门标志。

出口位置必须由 `ports` 计算，不允许固定放在房间右下角。

### 2. 连通关系层

- 默认不显示完整长线。
- 玩家当前房间的所有相邻出口使用金色高亮。
- 可达房间显示明确的“可达”角标和金色边框。
- 悬停或键盘聚焦任意房间时，仅高亮它、相邻房间及相关出口。
- 增加“显示连通图”开关；开启后才显示全部低亮度示意路径。
- 示意路径只能位于房间间空白、公共回廊或画布边缘通道，不穿过无关房间内部。

### 3. 动画层

- 移动路径保留在 SVG 中，但默认 `opacity: 0`，只供 `getPointAtLength()` 采样。
- 播放事件时仅临时显示当前活动路径，可使用短暂金色流光。
- 动画结束后立即清理活动样式，不留下残影。
- `prefers-reduced-motion` 下直接切换位置和楼层，不显示流光。

## 风险与控制

### 风险 1：门标志过多导致画面拥挤

- 默认只保留低亮度端点。
- 完整连通图默认关闭。
- 移动端使用简化图标和更小 label。

### 风险 2：修改路径后破坏移动动画

- 先分离 motion path 和 connector visual，再改坐标。
- 每种连接至少保留一个专门动画用例。
- 找不到 motion path 时保持当前回退。

### 风险 3：门框与现有房间美术不贴合

- 优先使用 CSS/SVG 端点徽记表达配对门。
- 只有物理 seam 使用完整门框。
- 不为解决 UI 问题直接重绘最终合成图。

### 风险 4：新字段影响旧世界包

- `visual` 保持可选。
- 缺字段时继续使用旧低亮度路线回退。
- 增加无 `visual` 绑定的兼容测试。

### 风险 5：公开连通图泄露角色信息

- 连通图只包含 `world.json` 的公开地点拓扑。
- 所有 token、计数、立绘请求和动画仍从当前视图的 agents 集合产生。

## 完成标准

只有同时满足以下条件才视为修复完成：

1. 一楼所有规则连接都有清晰的门、通道、石阶或楼梯表达。
2. 默认视图中不存在意义不明的常驻长线或点状调试线。
3. 13 条连接在完整连通图模式下均可追踪。
4. 路径首尾、端口和可见入口一致；没有 64px 偏差或非法零长度 SVG。
5. 当前相邻地点与行动系统允许选择的目标完全一致。
6. 同层、室外、地窖和跨层移动动画全部通过。
7. 玩家信息隔离测试通过。
8. 三种目标视口通过视觉验收。
9. 旧世界绑定和无绑定回退继续工作。
10. 用户审阅修改后截图并明确认可。

## 审阅时需要确认的设计选择

本文推荐以下默认值：

1. 默认不显示完整连通线，只显示建筑出口和当前可达关系。
2. 提供“显示连通图”开关供玩家查看全部拓扑。
3. 物理接缝使用完整门框；其他同层连接使用配对门标志，避免假装房间真实相邻。
4. 复用现有 v002 门框、楼梯和石阶，不开启新一轮生图。
5. 连通图属于公开地图信息，但绝不显示远处角色或楼层真实人数。

只有用户确认上述方向后，才进入 Repair mode 的实际修改阶段。
